# Documentation

1. Identify the intended reader and the task they need to complete.
2. Use exact commands, paths, expected output, and recovery steps where relevant.
3. Keep facts synchronized with current code and configuration; do not document unverified behavior.
4. Separate tutorials, how-to guides, references, and explanations when the audience benefits.
5. Verify links, commands, and examples before publishing.
