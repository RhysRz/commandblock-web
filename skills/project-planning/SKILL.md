# Project Planning

1. Inspect the repository, current changes, constraints, and related code before proposing work.
2. State the goal, acceptance criteria, risks, and files likely to change.
3. Split work into independently testable tasks in dependency order.
4. Identify actions requiring confirmation: destructive changes, credentials, payments, or external publishing.
5. Write a concise plan, then execute only after the user approves the scope.
